# What is GIMBAP?

**GIMBAP** (Go Injection Management for Better Application Programming) is a modern, opinionated web framework for Go that brings enterprise-level development patterns to the Go ecosystem.

import { FeatureCard, FeatureGrid } from '../../components/FeatureCard';

## The Problem GIMBAP Solves

Building scalable web applications in Go often means manually wiring dependencies, repetitive boilerplate code, and

 lack of structure as projects grow. While Go's simplicity is powerful, it can become a burden in large enterprise applications.

<Callout type="info">
GIMBAP was born from real-world frustration with managing dependencies in growing Go applications. It brings the best patterns from NestJS and Spring Boot to the Go world, adapted for Go's philosophy.
</Callout>

## Philosophy

Like the Korean dish it's named after (gimbap - seaweed rice rolls), GIMBAP wraps all your application components together in a cohesive, easy-to-manage structure:

```
┌─────────────────────────────────────┐
│  🌊 Module (Seaweed wrapper)       │
│  ┌──────────────────────────────┐  │
│  │  🍚 Controllers               │  │
│  │  🥕 Services (Providers)      │  │
│  │  🥒 Repositories              │  │
│  │  🥚 Dependencies              │  │
│  └──────────────────────────────┘  │
│                                     │
│  All wrapped together seamlessly   │
└─────────────────────────────────────┘
```

## Core Principles

### 1. **Automatic Dependency Injection**

No more manual wiring. Define what you need, and GIMBAP handles the rest:

```go
// Just add parameters to your constructor
func NewUserService(db *Database, logger *Logger) *UserService {
    return &UserService{DB: db, Logger: logger}
}

// GIMBAP automatically provides db and logger!
```

### 2. **Module-First Architecture**

Organize code by features, not file types. Each module is self-contained and reusable:

```go
var UserModule = gimbap.DefineModule(gimbap.ModuleOption{
    Name: "UserModule",
    Providers: []*gimbap.Provider{UserService, UserRepository},
    Controllers: []*gimbap.Controller{UserController},
    SubModules: []*gimbap.Module{AuthModule, DatabaseModule},
})
```

### 3. **Pluggable Architecture**

Switch HTTP engines without changing your code:

```go
// Use Gin
ServerEngine: gin_engine.NewGinHttpEngine()

// Or Fiber
ServerEngine: fiber_engine.NewFiberHttpEngine()

// Or Echo
ServerEngine: echo_engine.NewEchoHttpEngine()
```

### 4. **Type-Safe**

Leverages Go's type system for compile-time safety:

```go
// Get providers with type safety
userService := gimbap.GetProvider(app, UserService{})
// Type: *UserService - fully type-checked!
```

## Who Should Use GIMBAP?

### ✅ Perfect For:

- **Enterprise Applications**: Large-scale applications with complex dependency graphs
- **Team Projects**: Clear structure and patterns for team collaboration
- **Microservices**: Building multiple services with shared modules
- **Developers from NestJS/Spring**: Familiar patterns adapted for Go
- **API-First Development**: RESTful APIs with clean architecture

### ⚠️ Consider Alternatives If:

- **Simple CRUD Apps**: For very simple apps, standard library might be enough
- **Embedded Systems**: GIMBAP uses reflection, adding some overhead
- **Ultra Low-Level**: If you need absolute control over every detail

## How It Compares

| Feature | GIMBAP | Gin/Fiber/Echo | Standard Library |
|---------|--------|---------------|------------------|
| Dependency Injection | ✅ Automatic | ❌ Manual | ❌ Manual |
| Modular Architecture | ✅ Built-in | ⚠️ DIY | ⚠️ DIY |
| Auto Route Registration | ✅ Yes | ❌ Manual | ❌ Manual |
| Engine Swapping | ✅ Yes | ❌ No | N/A |
| Learning Curve | Medium | Low | Low |
| Enterprise Patterns | ✅ Yes | ❌ No | ❌ No |
| Performance | Fast | Faster | Fastest |
| Best For | Large Apps | Medium Apps | Small Apps |

<Callout type="tip">
GIMBAP doesn't replace Gin/Fiber/Echo - it uses them under the hood! You get the performance of these frameworks with added structure.
</Callout>

## Quick Example

Here's a complete GIMBAP application in ~50 lines:

```go
package main

import (
    "github.com/gin-gonic/gin"
    "github.com/jhseong7/gimbap"
    gin_engine "github.com/jhseong7/gimbap/external/engine/gin"
)

// Service with dependency
type UserService struct {
    DB *Database
}

func NewUserService(db *Database) *UserService {
    return &UserService{DB: db}
}

// Controller with automatic routing
type UserController struct {
    UserService *UserService
}

func (c *UserController) GetRouteSpecs() []gimbap.RouteSpec {
    return []gimbap.RouteSpec{
        {Method: "GET", Path: "/users", Handler: c.GetUsers},
    }
}

func (c *UserController) GetUsers(ctx *gin.Context) {
    // Your handler logic
    ctx.JSON(200, gin.H{"users": []string{"Alice", "Bob"}})
}

func NewUserController(service *UserService) *UserController {
    return &UserController{UserService: service}
}

// Define providers and module
var (
    DBProvider = gimbap.DefineProvider(gimbap.ProviderOption{
        Name: "Database", Instantiator: NewDatabase,
    })

    UserServiceProvider = gimbap.DefineProvider(gimbap.ProviderOption{
        Name: "UserService", Instantiator: NewUserService,
    })

    UserControllerProvider = gimbap.DefineController(gimbap.ControllerOption{
        Name: "UserController", Instantiator: NewUserController, RootPath: "/api",
    })

    AppModule = gimbap.DefineModule(gimbap.ModuleOption{
        Name: "AppModule",
        Providers: []*gimbap.Provider{DBProvider, UserServiceProvider},
        Controllers: []*gimbap.Controller{UserControllerProvider},
    })
)

func main() {
    app := gimbap.CreateApp(gimbap.AppOption{
        AppName:      "UserAPI",
        AppModule:    AppModule,
        ServerEngine: gin_engine.NewGinHttpEngine(),
    })

    app.Run(gimbap.RuntimeOptions{Port: 8080})
}
```
