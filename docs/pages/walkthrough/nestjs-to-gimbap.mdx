# Porting NestJS Applications to GIMBAP

This comprehensive guide will help you migrate your NestJS applications to GIMBAP, Go's dependency injection web framework. We'll cover everything from basic setup to advanced patterns.

## Overview

NestJS and GIMBAP share similar architectural principles:
- Dependency Injection (DI)
- Modular architecture
- Separation of concerns
- Decorator/annotation-based programming (NestJS) vs explicit registration (GIMBAP)

### Key Differences

| Feature | NestJS | GIMBAP |
|---------|---------|---------|
| Language | TypeScript/JavaScript | Go |
| Decorators | `@Injectable()`, `@Controller()` | Explicit registration with `DefineProvider()` |
| DI Container | Built-in | Multiple backends (native, Fx, Wire) |
| HTTP Engines | Express/Fastify | Gin/Fiber/Echo |
| Type Safety | Runtime + compile-time | Compile-time only |
| Async Model | Promises/async-await | Goroutines |

## Getting Started

### Prerequisites

- Basic knowledge of both NestJS and Go
- Go 1.21+ installed
- Understanding of dependency injection concepts

### Quick Comparison

#### NestJS Project Structure
```
src/
├── app.module.ts
├── app.controller.ts
├── app.service.ts
├── main.ts
└── users/
    ├── users.module.ts
    ├── users.controller.ts
    ├── users.service.ts
    └── dto/
        └── create-user.dto.ts
```

#### GIMBAP Project Structure
```
cmd/
├── main.go
internal/
├── app/
│   └── module.go
├── users/
│   ├── module.go
│   ├── controller.go
│   ├── service.go
│   └── dto.go
└── config/
    └── config.go
```
