# Porting Spring Boot Applications to GIMBAP

This comprehensive guide helps Java developers migrate their Spring Boot applications to GIMBAP, maintaining familiar architectural patterns while leveraging Go's performance and simplicity.

## Overview

Spring Boot and GIMBAP share fundamental principles:
- Dependency Injection (DI) at the core
- Modular architecture
- Convention over configuration (with different approaches)
- Enterprise-ready features

### Philosophical Differences

| Aspect | Spring Boot | GIMBAP |
|--------|------------|---------|
| Configuration | Annotation-driven with magic | Explicit registration |
| DI Container | Runtime reflection | Compile-time safety |
| Component Discovery | Classpath scanning | Manual module definition |
| Type System | Runtime + compile-time | Compile-time only |
| Concurrency | Thread pools & executors | Goroutines & channels |
| Memory Model | JVM garbage collection | Go garbage collection |

## Getting Started

### Prerequisites

- Solid understanding of Spring Boot concepts
- Go 1.21+ installed
- Basic knowledge of Go syntax and idioms
- Understanding of pointers in Go

### Migration Strategy

1. **Start Small**: Begin with a single microservice or module
2. **Maintain Architecture**: Keep your layered architecture (Controller → Service → Repository)
3. **Gradual Migration**: Run Spring Boot and GIMBAP services side by side
4. **Test Thoroughly**: Go's type system will catch many errors at compile time

## Key Concept Mappings

### Annotations to Functions

| Spring Boot | GIMBAP | Purpose |
|-------------|---------|----------|
| `@SpringBootApplication` | `gimbap.CreateApp()` | Application entry point |
| `@Component/@Service` | `DefineProvider()` | Injectable component |
| `@RestController` | `DefineController()` | HTTP endpoint handler |
| `@Configuration` | `DefineModule()` | Configuration class |
| `@Bean` | Provider function | Bean definition |
| `@Autowired` | Constructor params | Dependency injection |
| `@Value("${...}")` | Config service | Property injection |
| `@RequestMapping` | `GetRouteSpecs()` | Route mapping |

### Project Structure Comparison

#### Spring Boot Structure
```
src/main/java/
├── com/example/app/
│   ├── Application.java          # @SpringBootApplication
│   ├── config/                   # @Configuration classes
│   ├── controller/               # @RestController classes
│   ├── service/                  # @Service classes
│   ├── repository/               # @Repository interfaces
│   ├── entity/                   # JPA entities
│   └── dto/                      # Data transfer objects
src/main/resources/
├── application.yml               # Configuration
└── application-{profile}.yml     # Profile-specific config
```

#### GIMBAP Structure
```
cmd/
├── main.go                       # Application entry point
internal/
├── app/
│   └── module.go                # Root module definition
├── config/
│   ├── config.go                # Configuration structs
│   └── module.go                # Config module
├── controller/                   # HTTP controllers
├── service/                      # Business logic
├── repository/                   # Data access
├── entity/                       # Domain models
└── dto/                         # Data transfer objects
```

## Best Practices

### 1. Embrace Go Idioms
- Use errors instead of exceptions
- Leverage interfaces for abstraction
- Keep it simple and explicit

### 2. Type Safety
- Always check pointer vs value types
- Use compile-time checks
- Avoid interface{} when possible

### 3. Concurrency
- Use goroutines wisely
- Communicate via channels
- Avoid shared state

### 4. Testing
- Write table-driven tests
- Use interfaces for mocking
- Test early and often

## Common Pitfalls

### 1. Assuming Magic
Spring Boot does a lot behind the scenes. GIMBAP requires explicit configuration.

### 2. Pointer Confusion
```go
// Wrong - loses reference
type Service struct {
    repo Repository  // Should be *Repository
}

// Correct
type Service struct {
    repo *Repository
}
```

### 3. Ignoring Error Handling
Go requires explicit error handling:
```go
// Java: throws exception
// Go: returns error
user, err := service.GetUser(id)
if err != nil {
    // Handle error
}
```

### 4. Overusing Goroutines
Not every `@Async` method needs a goroutine. Consider the overhead.
